# 账单标签功能设计文档 (V1.4)

> 版本：V1.4 | 状态：实施中 | 日期：2026-05-30

---

## 1. 需求概述

为账单增加**标签（Tag）**能力，支持用户在记账时为账单打标签、查看标签、创建新标签、按标签筛选等。

### 1.1 已有基础

- ✅ 数据库表：`bill_tag` / `bill_tag_rel` 已建好（[001_schema_ddl.sql](../../004.数据库脚本(DBA)/001_schema_ddl.sql#L96-L118)）
- ✅ 实体类：`BillTag` / `BillTagRel` 已定义
- ✅ Mapper：`BillTagMapper` / `BillTagRelMapper` 已定义
- ❌ 无 API、无前端、无业务逻辑

### 1.2 核心交互方案

用户在**记账页**（record.html）的备注下方看到已有标签的 chip 列表，点击选中/取消，末尾有「+ 新建」按钮可弹窗创建新标签。保存账单时将选中的标签 ID 一并提交。

## 2. API 设计

### 2.1 标签管理路由

| 方法 | 路径 | 说明 | 请求体 | 成功返回 | 错误码 |
|------|------|------|--------|----------|--------|
| `GET` | `/finance/tags` | 获取用户所有标签 | 无 | `{ list: [{id, name, bill_count}] }` | 401 |
| `POST` | `/finance/tags` | 创建标签 | `{name: string}` | `{ id: Long }` | 400（空名/超长/重复）、401 |
| `PUT` | `/finance/tags/{id}` | 修改标签名 | `{name: string}` | 空 | 400（空名/超长/重复）、404 |
| `DELETE` | `/finance/tags/{id}` | 删除标签 | 无 | 空 | 404 |

**约束规则**：
- 标签名 1–16 字符（与 DDL `VARCHAR(16)` 一致）
- 同一用户下标签名唯一（数据库 `uk_user_name` 索引）
- 删除标签时，级联删除 `bill_tag_rel` 中的关联记录
- 所有接口需 JWT 认证

### 2.2 账单接口变更

#### `POST /api/bills` — 创建账单

**请求体变更**：新增 `tag_ids` 字段（可选）

```json
{
  "type": "EXPENSE",
  "amount": 45.00,
  "category_id": 3,
  "remark": "午餐",
  "bill_time": "2026-05-30 12:00:00",
  "tag_ids": [1, 5]          // ← 新增，可选数组
}
```

**逻辑**：
1. 若 `tag_ids` 未传 → 不处理标签
2. 若 `tag_ids` 为空数组 `[]` → 不关联标签
3. 若 `tag_ids` 有值 → 验证每个 tag_id 属于当前用户后，批量插入 `bill_tag_rel`
4. 每账单最多关联 **10 个标签**，超出时返回 400

#### `PUT /api/bills/{id}` — 更新账单

**请求体变更**：同上，新增 `tag_ids`（可选）

**逻辑**：
1. 若 `tag_ids` 为 `null`（未传）→ **不动**标签关联
2. 若 `tag_ids` 为空数组 `[]` → 删除该账单所有标签关联
3. 若 `tag_ids` 有值 → **全量替换**该账单的标签关联（先删旧再插新）

#### `GET /api/bills` — 账单列表

**查询参数变更**：新增 `tag_id` 参数（可选）

**返回变更**：每条账单增加 `tags` 字段

**逻辑**：
- 若传入 `tag_id` → 通过 `INNER JOIN bill_tag_rel` 筛选出关联该标签的账单
- 返回的每条账单附带 `tags: [{id, name}]` 字段

```json
{
  "code": 0,
  "data": {
    "list": [
      {
        "id": 123,
        "type": "EXPENSE",
        "amount": 45.00,
        "tags": [              // ← 新增
          {"id": 1, "name": "必要"},
          {"id": 5, "name": "报销"}
        ],
        ...
      }
    ],
    "total": 1,
    "page": 1,
    "pageSize": 50
  }
}
```

#### `GET /api/bills/{id}` — 账单详情

同上，返回结果增加 `tags` 字段。

#### `DELETE /api/bills/{id}` — 删除账单

**逻辑变更**：删除账单前先删除 `bill_tag_rel` 中该账单的关联记录。

### 2.3 导出接口变更

`GET /api/bills/export`（CSV/Excel）的导出结果增加「标签」列，标签以逗号分隔显示在同一单元格内。

#### 3.1.3 BillServiceImpl 标签关联逻辑

```java
// create() 中：
if (dto.getTagIds() != null && !dto.getTagIds().isEmpty()) {
    // 验证每个 tag_id 属于当前用户
    for (Long tagId : dto.getTagIds()) {
        BillTag tag = billTagMapper.selectById(tagId);
        if (tag == null || !tag.getUserId().equals(userId)) {
            throw new BusinessException(400, "标签不存在");
        }
    }
    // 批量插入关联
    for (Long tagId : dto.getTagIds()) {
        BillTagRel rel = new BillTagRel();
        rel.setBillId(bill.getId());
        rel.setTagId(tagId);
        billTagRelMapper.insert(rel);
    }
}

// update() 中：
if (dto.getTagIds() != null) {
    // 先删旧
    billTagRelMapper.delete(new LambdaQueryWrapper<BillTagRel>()
        .eq(BillTagRel::getBillId, id));
    // 再插新（同 create 逻辑）
}

// delete() 中：
billTagRelMapper.delete(new LambdaQueryWrapper<BillTagRel>()
    .eq(BillTagRel::getBillId, id));

// list() / getById() 中：
// 通过 LEFT JOIN 查询 tags，组装到返回的 Map 中
```

#### 3.2.3 Node.js 标签关联逻辑

```javascript
// POST /api/bills 中：
const { tag_ids } = req.body;
if (tag_ids && tag_ids.length > 0) {
    // 验证标签归属
    const [[{ count }]] = await pool.query(
        'SELECT COUNT(*) AS count FROM bill_tag WHERE id IN (?) AND user_id = ?',
        [tag_ids, user.id]
    );
    if (count !== tag_ids.length) {
        return res.status(400).json({ code: 400, msg: '部分标签不存在' });
    }
    // 批量插入
    const relValues = tag_ids.map(id => [billId, id]);
    await pool.query('INSERT INTO bill_tag_rel (bill_id, tag_id) VALUES ?', [relValues]);
}

// GET /api/bills 中：
// 增加子查询或 LEFT JOIN 获取 tags
const [rows] = await pool.query(`
    SELECT b.*, c.name AS category_name, c.icon AS category_icon,
           (SELECT JSON_ARRAYAGG(JSON_OBJECT('id', bt.id, 'name', bt.name))
            FROM bill_tag_rel btr
            JOIN bill_tag bt ON btr.tag_id = bt.id
            WHERE btr.bill_id = b.id) AS tags
    FROM bill b ...
`);
// PUT /api/bills/:id 中（全量替换 tag_ids）：
const { tag_ids } = req.body;
if (tag_ids !== undefined) {
    await pool.query('DELETE FROM bill_tag_rel WHERE bill_id = ?', [req.params.id]);
    if (tag_ids.length > 0) {
        const relValues = tag_ids.map(id => [req.params.id, id]);
        await pool.query('INSERT INTO bill_tag_rel (bill_id, tag_id) VALUES ?', [relValues]);
    }
}

// DELETE /api/bills/:id 中（级联删除关联）：
await pool.query('DELETE FROM bill_tag_rel WHERE bill_id = ?', [req.params.id]);
await pool.query('DELETE FROM bill WHERE id = ? AND user_id = ?', [req.params.id, user.id]);
```

## 4. 前端设计

### 4.1 记账页（record.html）

#### 新增 UI 元素

在**备注输入区下方**新增标签选择器区域：

```
┌─────────────────────────────────┐
│ [✏️ 添加备注...]                 │ ← 现有备注输入框
├─────────────────────────────────┤
│ 标签                              │ ← 标签区域标题
│                                 │
│ [必要] [冲动消费] [报销] [+ 新建] │ ← chip 列表 + 新建按钮
│                                 │
└─────────────────────────────────┘
```

**交互逻辑**：
1. 页面加载时调用 `GET /finance/tags` 获取用户标签列表
2. 渲染为 chip，最多显示 12 个（超出则横向滚动），末尾固定「+ 新建」chip
3. 点击已有 chip → 切换选中/未选中状态（选中态：蓝色高亮 `#E8F0FE`，蓝色边框 `#004ac6`）
4. 点击「+ 新建」→ 弹出底部输入框，输入标签名后确认：
   - 调用 `POST /finance/tags` 创建
   - 新 chip 自动出现在列表中并选中
   - 标签名重复时提示「该标签已存在」
5. 保存账单时，将选中的标签 ID 数组通过 `tag_ids` 字段随 payload 一并提交
6. **编辑模式**（URL 有 `?edit=` 参数）：加载账单详情后回填选中的标签 chip

#### 标签新建弹窗

```
┌─────────────────────────────────┐
│ 新建标签                         │
│ [输入标签名称 (最多 16 个字符)]   │
│                                 │
│ [取消]        [确认]            │
└─────────────────────────────────┘
```

- 输入框：16 字符限制
- 确认按钮：若输入为空或超过 16 字符则禁用
- 已有标签名重复时，后端返回 409/400 错误，前端 toast 提示

## 6. 错误处理

| 场景 | 错误码 | 提示信息 |
|------|--------|----------|
| 标签名为空 | 400 | 标签名不能为空 |
| 标签名超长 | 400 | 标签名不能超过 16 个字符 |
| 标签名重复 | 400 | 该标签已存在 |
| 标签不属于当前用户 | 400 | 部分标签不存在 |
| 标签不存在 | 404 | 标签不存在 |
| 每账单标签数超上限 | 400 | 每笔账单最多关联 10 个标签 |
| 账单不存在 | 404 | 账单不存在 |
| 未授权 | 401 | 请先登录 |

## 7. 测试要点

1. **标签 CRUD**：创建、查询、修改、删除标签
2. **标签去重**：同一用户创建同名标签应报错
3. **账单关联**：创建账单时传入 tag_ids 正确关联
4. **标签上限**：创建账单时传入超过 10 个 tag_ids 应返回 400
5. **全量替换**：更新账单 tag_ids 为 `[]` 时清空关联
6. **不传不动**：更新账单时不传 tag_ids 字段，关联不变
7. **级联删除**：删除账单时关联记录同步删除
8. **标签删除**：删除标签时 bill_tag_rel 关联同步删除
9. **列表返回**：账单列表接口正确返回 tags 字段
10. **前端交互**：选中标 chip、新建标签、编辑回填、标签展示
